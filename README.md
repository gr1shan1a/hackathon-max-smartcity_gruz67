# MAX Дом — Цифровой сервис управления многоквартирным домом
### Хакатон «Умный город» (Платформа для бизнеса в мессенджере MAX)
**Команда:** «Груз 67»  
**Среда реализации:** Мессенджер MAX (Чат-бот + подключенное WebApp мини-приложение)

---

Актуальные команды запуска, настройка PostgreSQL, подключение HTTPS-ссылки в MAX
и ограничения демо описаны в [RUNNING.md](./RUNNING.md).

## 1. Назначение решения
«MAX Дом» — это экосистема для жителей, собственников помещений, совета МКД и управляющих организаций, встроенная непосредственно в мессенджер MAX. Сервис переводит управление домом из разрозненных чатов и бумажных квитанций в прозрачный цифровой формат:
* Оперативное информирование об авариях и отключениях коммунальных ресурсов в режиме реального времени.
* Публичный трекинг заявок в УК с возможностью поддержки (коллективный апвоут) или опровержения соседями.
* Планирование и голосование за удобное время общедомовых собраний (ОСС) с контролем кворума и экспортом в календарь (`.ics`).
* Прозрачные счета за ЖКУ с интерактивным мануалом подачи показаний счетчиков и напоминаниями о задолженности.
* Закрепленный крытый паркинг и оформление гостевых пропусков на шлагбаум в 1 клик.
* Вежливая «Авто-жалоба» на неправильно припаркованные автомобили (уведомление владельца через бота без скандалов).
* Конфиденциальная связь с соседом по номеру квартиры без раскрытия персональных номеров телефонов.
* Справочник контактов: персональный участковый уполномоченный полиции по району, график дежурств специалистов (с X до X) и расписание вывоза мусора (ТКО/КГО).
* Внутридомовая барахолка и услуги мастеров-соседей («Авито» и «Профи.ру» для дома).

---

## 2. Основной пользовательский сценарий

### Сценарий жителя (As Is ➔ To Be):
1. **As Is (как сейчас):** Житель замечает неисправность лифта или протечку. Пишет в неформальный чат дома на 300 человек. Сообщение тонет в флуде. Непонятно, передана ли заявка в диспетчерскую. Параллельно жители дублируют звонки в УК, перегружая диспетчера.
2. **To Be (с «MAX Дом»):**
   - Житель открывает мини-приложение в MAX-боте.
   - Видит аварийный баннер: если заявка уже подана соседом Михаилом из кв. 38, житель нажимает **«Подтверждаю (+19)»**, повышая приоритет в диспетчерской без дублирования звонков.
   - Если проблема новая — нажимает **«Подать заявку»**, выбирает категорию («Лифты»), делает фото. Заявке присваивается номер `TCK-142` и назначается дежурный мастер с прямым контактом.
   - Владельцу приходит push-уведомление в MAX об изменении статуса: *«Мастер приступил к работе»* ➔ *«Заявка выполнена»* с фотоотчетом.

## 3. Состав и архитектура решения

```
┌───────────────────────────────────────────────────────────────┐
│                    Мессенджер MAX Client                      │
│   (Мобильное приложение iOS / Android / Web / Desktop)        │
└──────────────┬────────────────────────────────┬───────────────┘
               │                                │
    Команды и уведомления               MAX Bridge / WebApp
               │                                │
               ▼                                ▼
┌──────────────────────────────┐   ┌────────────────────────────┐
│      MAX Bot Webhook         │   │   MAX Дом WebApp Frontend  │
│  (Команды, Push, Напоминания)│   │  (React 18 + Tailwind v4 + │
│                              │   │  Emil Kowalski Animations) │
└──────────────┬───────────────┘   └────────────┬───────────────┘
               │                                │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │    Node.js Express REST API    │
               │   (OpenAPI 3.1 & DATA-API)     │
               └───────────────┬────────────────┘
                               ▼
               ┌────────────────────────────────┐
               │     PostgreSQL / JSONB DB       │
               │  (Заявки, ЖКУ, ОСС, Парковка)  │
               └────────────────────────────────┘
```

* **Frontend:** React 19, TypeScript, Tailwind CSS v4, Lucide Icons, Sonner (стек уведомлений), Canvas Confetti. Дизайн-система построена по стандартам **Эмиля Ковальски** (пружины, кривые `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`, `:active { transform: scale(0.97) }`, запрет `scale(0)`).
* **Backend:** Node.js, Express, TypeScript, REST API, iCalendar `.ics` генератор, Webhook-обработчик для MAX-бота.
* **Nginx Reverse Proxy:** Маршрутизация статики и API-запросов.

## 4. Запуск одной командой через Docker

Все компоненты решения запускаются одной командой:

```bash
docker compose up -d --build
```

Время полной сборки и запуска: **менее 2 минут**.

После запуска сервисы доступны по адресам:
* **Веб-интерфейс / Мини-приложение:** [http://localhost:5173](http://localhost:5173) (порт задаётся `FRONTEND_PORT`)
* **REST API & Healthcheck через frontend:** [http://localhost:5173/api/health](http://localhost:5173/api/health)
* **OpenAPI спецификация:** [openapi.yaml](./openapi.yaml)
* **Файл автоматической проверки жюри:** [DATA-API.yaml](./DATA-API.yaml)

## 5. Необходимые параметры и переменные окружения

Файл `.env.example` находится в корне репозитория. Для локального запуска нужны `.env`, `DATABASE_URL` и `DEMO_MODE=true`; Docker Compose задаёт соединение с БД автоматически.

| Переменная | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `MAX_BOT_TOKEN` | Токен чат-бота от платформы MAX | `test_token_max` |
| `PORT` / `BACKEND_PORT` | Порт API бэкенда | `3001` |
| `FRONTEND_PORT` | Порт веб-приложения | `5173` / `80` |
| `NODE_ENV` | Режим работы окружения | `production` |

## 8. Внешние сервисы и интеграции

1. **MAX Messenger Platform:**

   - WebApp интерактивная кнопка для открытия мини-приложения внутри диалога.

3. **Платежный шлюз (СБП):**
   - Симуляция безопасной оплаты ЖКУ в 1 клик с моментальным обновлением баланса лицевого счета.

## 9. Описание работы с данными

* Система оперирует моделью многоквартирного дома (ЖК «Северное Сияние», 196 квартир, 4 подъезда).
* Состояние хранится в PostgreSQL с миграциями, транзакциями и отдельными личными данными пользователей. Повторный запуск сохраняет изменения.
* При недоступности API интерфейс сообщает об ошибке; операции не выдаются за успешно сохранённые.

## 11. Пошаговый сценарий проверки жюри

1. **Шаг 1: Запуск и проверка статуса**
   - Выполнить `docker compose up -d`
   - Открыть в браузере `http://localhost:5173`
   - Убедиться, что отображается шапка с ЖК «Северное Сияние», кв. 42 и предупреждение об аварии.
2. **Шаг 2: Проверка экстренной помощи и аварий**
   - Нажать на плашку «Авария / Отключение» ➔ изучить сроки и зону отключения ГВС.
   - Нажать красную кнопку **SOS** ➔ проверить контакты 112, круглосуточной диспетчерской (+7 495 700-11-22).
3. **Шаг 3: Заявки в УК и коллективный апвоут**
   - Перейти во вкладку **«Заявки»**.
   - Нажать кнопку **«Подтверждаю»** у заявки `#TCK-142` (застрял лифт) ➔ счетчик увеличится до 20, приоритет повысится.
   - Нажать **«Подать заявку»** ➔ создать обращение по домофону или сантехнике ➔ убедиться, что заявка мгновенно появляется в ленте.
4. **Шаг 4: ЖКУ, счетчики и крытая парковка**
   - Перейти во вкладку **«ЖКУ & Паркинг»**.
   - Нажать **«Оплатить через СБП»** ➔ сработает анимация конфетти, статус сменится на «Оплачено», задолженность обнулится.
   - Нажать **«Инструкция»** в блоке счетчиков ➔ изучить правила списания показаний и отправить тестовые значения.
   - В блоке парковки нажать **«Оформить гостевой пропуск»** на место P-42 ➔ сгенерируется QR-пропуск для шлагбаума.
5. **Шаг 5: Собрания ОСС и добавление в календарь**
   - Перейти во вкладку **«ОСС»**.
   - Нажать на временной слот (например, «Вт, 29 сен в 20:00») ➔ шкала голосов динамически пересчитается.
   - Нажать **«Добавить в календарь»** ➔ скачается валидный файл `.ics`.
6. **Шаг 6: Связь с соседом и авто-жалоба**
   - Нажать кнопку быстрого действия **«Чат в кв.»** ➔ отправить сообщение в квартиру № 48 (номера скрыты).
   - Нажать **«Авто-жалоба»** ➔ ввести госномер нарушителя `А987ВС 199` ➔ бот зафиксирует отправку предупреждения.
7. **Шаг 7: Режим MAX WebApp Frame**
   - Нажать в шапке кнопку **«Браузер / MAX WebApp»** ➔ интерфейс переключится в нативную рамку смартфона с фирменной шапкой мессенджера MAX.

## 12. Примеры ожидаемого поведения системы

* **Отклик кнопок:** Нажатие на любую кнопку сопровождается тактильным сжатием (`scale(0.97)`), длительность анимаций не превышает 240ms.
* **Уведомления:** Каждое действие подтверждается тостом Sonner в верхней части экрана.
* **API проверки:** Запросы к эндпоинтам возвращают строгие JSON-структуры с HTTP-кодами `200` и `201` согласно `DATA-API.yaml`.

## 13. Известные ограничения MVP

* В демо доступны два тестовых профиля с независимым выбором в каждом браузере. Настоящая авторизация MAX пока не подключена; см. RUNNING.md.
* Оплата ЖКУ работает в тестовом режиме эмуляции СБП без списания реальных денежных средств.
* Распознавание госномеров автомобилей по фото является клиентской моделью (в продакшене подключается OCR-модуль платформы).
